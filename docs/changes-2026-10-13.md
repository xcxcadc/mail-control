# 全局查询、正文修复与秩序蓝白界面

本次版本将全站邮件查询、自定义发件及完整正文阅读同步到可维护源码，并统一 Mailu、扩展功能、Rspamd 和 SnappyMail 的界面。六个扩展功能集中在左侧“邮件工作台”，Rspamd 使用独立页面。

## 邮件和功能

- 全局查询扫描全部实际邮箱与 Maildir 文件夹，包含停用账户保留的邮件；15 秒自动刷新暂停于后台、选中邮件或阅读邮件时。
- 完整邮箱、域名及“前缀＋域名”均精确匹配。邮件身份支持 new→cur 迁移，未读查询包括 new 和 cur 中没有 Seen 标记的邮件。
- 单封和批量删除经过确认并使用 Dovecot 精确邮件标识，保持 IMAP 索引。生产复测取消确认，已有隔离数据删除验证记录；不能以取消操作声称实际删除成功。
- 自定义发件允许任意有效前缀和本站已有域名，不要求先创建发件账户；原营销和 API 发件账户约束保持。
- HTML 正文使用经过认证的独立文档，支持完整大邮件、CID 图片和附件。移除 1 MB 静默截断，清理器正确处理 base/embed 等无闭合标签，正文脚本与表单禁止执行。
- 修复营销 manage 兼容入口的 API 相对路径、跨域复制发件人及预览更新。
- 全局阅读区关闭时失效在途详情请求，防止迟到响应重新打开；桌面与手机布局切换仍能完成正常请求。

## 界面与响应

- 扩展页和 Rspamd 均在内容首帧提供完整导航，手机抽屉无需等待业务请求或额外管理页面。Rspamd 仅允许启用的全局管理员访问，由 Nginx HTML `sub_filter` 直接注入固定菜单、蓝白样式和抽屉交互，不使用 SSI，也不缓存用户身份。
- 新主题在内容首帧生效；桌面全局查询左列表、右阅读区，手机正文和其他弹窗自适应居中。
- 框架内的页面不再生成第二套 Mailu 导航。Rspamd 链接在当前页面打开，不再叠加旧插件菜单窗口。
- 手机域名列表优先保留域名与操作列，额外列通过现有展开方式查看。
- UI 资源按内容摘要版本化，减少重复主题请求。Rspamd 只缓存 GET/HEAD 的 JS、CSS、字体和图片；统计、邮件、配置与鉴权数据不套用该策略。
- 缓存变量在 Nginx rewrite break 之前赋值；Rspamd 主题脚本异步加载，不阻塞 RequireJS、DOMReady 或 Bootstrap 插件注册。

## 实际验证

本地 Python 36 项业务回归通过。桌面 1440×1000、手机 390×844 浏览器测试覆盖 9 个生成页、正文、导航、单次初始化请求、迟到详情及阅读布局转换，全部使用本地仿真数据。

生产原生页面检查包括域名、设置、自动回复、密码、令牌、管理员、中继域、公告和客户端设置；普通用户仍没有全局管理入口及邮件权限。首帧 8 个桌面/手机条件共 1440 个内容帧没有旧主题、JavaScript 错误或横向溢出；Rspamd 桌面与手机首帧均直接含 22 个链接，嵌入 Rspamd 不显示侧栏且不占宽度。

通过部署用代理实测，Rspamd 修复缓存前再次加载约 15.8 秒；修复后约 4.4 秒，静态资源 transferSize 为 0。首次完整加载约 14.8 秒，网络与代理会影响时间；数据 API 保持 no-store。原生及工具菜单到 Rspamd 的实际跳转、Throughput/Configuration/Symbols/History/Status 五个页签通过。

本次正式部署仅替换前端覆盖配置并热加载 Nginx；应用与独立 mail-control 小服务均未重启，11 个业务容器没有重启。现有用户邮件和配置未用于写入测试。

## 邮件服务先前修复

自动回复故障来自缺少有效 POSTMASTER，导致 Dovecot Sieve 初始化失败。生产已设置有效 postmaster_address 并热加载；用户确认外部邮件收到自动回复。转发、别名、Sieve redirect/fileinto 与垃圾分流已用隔离邮箱验证。自动回复保留 vacation 的每日去重。

此仓库是独立 Mailu 扩展，邮件服务本身的主机配置及私密备份不纳入源码。新部署应检查合法 POSTMASTER、Dovecot/Sieve 和 587/143/110 STARTTLS 监听，按实际 Mailu 版本配置，避免复制生产机密。

## 后续修改

修改 `src/` 或 `ui/`，执行 `tools/build_ui.py`、Python 和浏览器回归，再提交推送。生成的应用和 Nginx 配置必须同版本发布；GitHub Actions 检查构建一致性与回归，不自动修改生产数据或部署。
