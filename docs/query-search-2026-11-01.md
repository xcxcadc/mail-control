# 全局邮件关键词查询与查询进度（2026-11-01）

## 查询方式

全局邮件查询保留原来的域名、邮箱前缀、完整邮箱、未读状态和文件夹精确筛选。关键词可选择：

- 全部（含正文）：邮箱、主题、发件人、收件人、抄送和正文。
- 仅主题、仅正文、仅发件人、仅收件人；收件人同时包含抄送地址。
- 中文、MIME 字符集、Base64、Quoted-Printable 和 HTML 可见文字均可检索；不把附件内容当作正文检索。

例如：选择“仅正文”并输入 `樱花隧道`，只返回正文包含该词的邮件；仅在主题出现该词的邮件不会混入。域名 `example.com` + 前缀 `support` 仍只匹配 `support@example.com`。

管理员接口 `GET /api/global/messages` 新增 `search_field=all|subject|body|from|to`，默认 `all`。关键词参数 `q` 与 `query` 均兼容，最长 1000 个字符；非法字段返回 HTTP 400。既有权限、分页和删除行为保持。

## 进度与刷新

查询、刷新和首次加载均显示不定进度条、当前阶段及实际耗时，不显示伪造百分比。请求期间保留已有结果，成功后更新；失败时保留结果并允许重试。

每个页面最多一个列表请求执行中，筛选条件改变时仅排队最新请求，旧结果不得覆盖新条件。同条件连续点击去重。自动刷新只在可见且空闲、无选中邮件时进行：无关键词每 5 秒，带关键词每 15 秒；后台页面暂停。

## 共机资源与投递边界

无关键词查询保持仅读取当前页邮件头的路径；正文按 64 KiB 分块解码，附件不整体加载。匹配缓存最多 512 条且只保存布尔值，文件 stat 变化即失效；正文冷扫描并发限制为 1，避免在 2 GiB 共机服务器上重复并发解码。

2026-11-01 只读检查样本中，SMTP 到本机 LMTP 投递耗时约 0.39–2.5 秒，队列为空；普通全局列表 API 约 0.08–0.10 秒。一个用户反馈样本的主要等待发生在到站前，不能据此归咎于 NekoPass。该检查不是所有外部邮箱投递时延的保证。

本次发布仅替换生成的 Mail Control 程序并重启 `mail-control.service`。NekoPass、PostgreSQL、V2bX、Mailu 容器及其启动时间均作为发布前后的保护项；详见 `production-cohosting.md`。

## 验证方法

- `python tools/build_ui.py` 生成部署产物。
- `python -m unittest -v test_mail_control.py test_query_search.py` 验证原有业务及 MIME、过滤、鉴权、缓存、并发等行为。
- `node test_query_progress.cjs` 在真实 Chrome 中检查查询、进度、错误恢复、并发及桌面/手机阅读布局；`PYTHON`、`NODE_PATH` 和 `CHROME_PATH` 可指向本机已有运行时。既有全页面回归 `test_ui_performance.cjs` 使用 `CHROMIUM_EXECUTABLE_PATH` 选择浏览器。
- `python tools/query_acceptance_server.py --port 4191 --delay-ms 2000` 启动只绑定回环的真实后端验收页，临时数据库/Maildir 仅含合成邮件，拒绝发信和修改。人工分别点击主题/正文查询并打开正文。完成后 Ctrl+C 清理临时数据。
- 生产发布前对候选程序校验哈希和 Python 3.10 语法，保留原文件以供自动回滚；发布后使用合成测试邮件验证实际主题/正文检索及受保护服务不变。

测试凭据、用户邮件正文、验证码、数据库、业务附件和服务器完整日志不得提交到仓库。
